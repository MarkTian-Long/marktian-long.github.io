# Blog Image Prompting Skill

版本：1.2｜更新：2026-11-28

本 Skill 将通用图像生成能力转化为适用于 marktian-long.github.io 的编辑插图工作方法。它负责**图片任务定义、逐图 Prompt Packet、模型交接、视觉探索、参考图和有界迭代**；不替代事实核验、图表语义规范、资产规格、网页预览或发布授权。

## 1. 何时使用

当文章已经明确需要一张独立图片，并且图片承担以下任务之一时使用：

- **Editorial hero**：帮助读者进入文章问题、矛盾或工作场景。
- **Concept / scene illustration**：把抽象机制、参与者或系统关系具象化。
- **Mechanism / relationship visual**：解释对象之间的关系、约束或作用机制。
- **Workflow comparison**：呈现引入前后工作方式、人工与 Agent 的分工变化。
- **Framework / hub visual**：帮助读者理解一套框架或多个后续研究方向。
- **Targeted image edit**：只修改已有图像的某个明确部分，并保留其他不变量。

不因文章很长、章节很多或页面显得单调而机械配图。纯数值图表、需要可核验精确数据的图、真实产品截图和论文原始证据图，分别走确定性图表或可核实来源素材，不用生图冒充。

## 2. 默认执行方式与安全边界

1. **默认使用当前环境内置的图像生成/编辑工具。** 在 ChatGPT 中使用 image_gen；不要求用户提供 API Key，不自动切换 CLI、API 或第三方工具。
2. 用户明确要求 CLI/API 时才走外部回退；内置工具不可用时，先如实说明，不静默切换。
3. 一次调用只对应一个明确的独立图片任务。不得把整篇文章交给模型生成网页截图、浏览器页面、网站 mockup 或“完整预览”。
4. 生图不是事实来源。不得让模型创造未经证实的产品 UI、客户 Logo、品牌标识、数据、引用、统计数字、实验场景或企业现场。
5. 真实产品界面、人物/事件现场、论文原图和证据截图优先使用可核实来源；不得用 AI 重绘冒充真实截图或现场照片。
6. 生图模型负责视觉创作与视觉探索；结构化逻辑源负责冻结准确的中文标签、数字、节点、箭头、表格和条件关系。模型输出可直接采用，但必须通过语义验收；需要时再用确定性层收口，不为形式要求牺牲准确性。
7. 候选图不等于合格资产。只有通过 tools/blog/IMAGE_REVIEW_CHECKLIST.md 才能进入文章或预览。

## 3. 先写图片简报，再写 Prompt

每张图先完成一份简短 brief：

- **位置**：要插入文章哪里？
- **读者任务**：读者看完应更容易理解什么？
- **唯一视觉命题**：这张图最重要的一件事是什么？
- **主体与动作**：画面里有什么对象，正在发生什么？
- **关系与约束**：谁与谁连接、对照、协作或受到限制？
- **证据边界**：哪些元素是事实，哪些只是概念隐喻？哪些不能虚构？
- **输出形态**：独立图片资产、比例、需要保留的裁切安全区。
- **文字策略**：无字、短标签，还是后期精确排版？

如果一句话说不清图片要表达什么，先回到正文澄清，不要用更长的 Prompt 掩盖未解决的内容问题。

### Prompt Scope Lock（强制）

- 全文只供助手理解，不作为 image_gen 的默认输入。当前图片的局部上下文最多两句，必要时再加一句主结论。
- 每篇文章只维护一个 tools/blog/visual-prompts/<slug>.md；每张图单独成块，记录 Brief、Final Prompt、参考图角色、状态和尝试日志。
- **实际调用只取当前图片块的 Final Prompt**，不把整个 Prompt Packet、全文、完整大纲、整篇预览或其他图片任务交给模型。
- 如果当前 ChatGPT 生图入口依赖对话上下文，调用前另发一条只含当前 Final Prompt 与必要风格锚点的干净交接消息；需要强隔离时，使用新会话，只载入该 Prompt 和必要参考图。保存文件本身不会自动隔离模型上下文。
- 简单概念/场景图优先用 1–3 句清晰 Prompt；复杂图才提供本图节点、连线、条件和短标签，不把其他章节摘要混入。
- 多节点图只有在节点属于同一明确框架/流程时才允许；不得把多个独立章节压成“全文总览”。
- 默认禁止全文总结海报、完整指南、全篇信息图、章节拼图和网页截图；除非作者明确要求全文总览或网页设计，否则不生成。
- 每次调用前检查实际交接文本，确认没有混入助手解释、流程建议、其他图片 Prompt 或无关上下文。

## 4. Prompt 结构

简单任务优先用 1–3 句清晰描述；复杂任务用短标签分段。不要机械填满所有字段，也不要用“高级、漂亮、专业、科技感”代替可见细节。

推荐顺序：

1. **Deliverable / Use case**：明确要生成的是独立博客插图，而不是网页或幻灯片。
2. **Purpose**：这张图解决什么阅读问题。
3. **Scene / Subject / Action**：环境、主体和正在发生的动作。
4. **Composition**：视角、景别、主焦点、空间层次、视觉动线、留白和裁切安全区。
5. **Style / Medium**：编辑插画、纸雕、3D 静物、摄影等具体媒介。
6. **Materials / Lighting / Palette**：表面质感、光源方向、阴影、色彩角色。
7. **Text**：无文字，或逐字给出短文案及位置/字体要求。
8. **Constraints / Avoid**：必须保留、不得添加和不得改变的内容。

完整模板与不同图片类型的可复制 Prompt 见 references/prompt-recipes.md。

## 5. 视觉质量：从“画了什么”推进到“如何呈现”

Prompt 至少要回答以下设计问题中的关键几项：

- **视觉主次**：第一眼看到谁？第二眼沿什么路径理解关系？
- **构图与空间**：主体如何占据画面？前、中、后景如何建立层次？是否需要留白？
- **视觉隐喻**：物体/场景为什么能代表文章机制？隐喻是否准确而不过度？
- **材质与光线**：纸、陶瓷、金属、玻璃、织物等材料如何帮助表达？光从哪里来？
- **色彩角色**：主色、强调色和背景色分别承担什么作用，而不是简单罗列色号。
- **原创性**：是否出现通用图库感、模板卡片、无意义科技装饰或千篇一律的机器人？
- **阅读尺度**：缩小到文章实际显示宽度后，焦点、主体和关键关系是否仍可辨认？

优先避免无必要的发光大脑、霓虹电路板、悬浮 UI、通用机器人头像、随机图标卡片、无意义数据流和图库式握手照片。只有当这些对象与文章事实或论点直接相关时才使用。

## 6. 生成与迭代

1. **默认只生成一个首轮候选**：只有确实需要比较两种不同视觉命题时，才允许最多两个首轮方向；差异必须体现在视觉隐喻、视角、空间组织或主体关系，不是只换颜色。
2. **先判断命题和构图，再判断细节**：主体与关系不对时，不要先修阴影、纹理或小装饰。
3. **一次只改一个主要变量**：例如只改主体位置、背景复杂度、光线方向或视觉层次。
4. **编辑时明确不变量**：每轮重复写明哪些对象、布局、颜色、透视、光线和裁切必须保持。
5. **风格锚点**：选定首图或一张代表图作为同篇视觉参考。后续引用时明确“只参考配色/材质/光线/笔触，不复制主体与构图”。
6. **不要堆 Prompt**：如果当前 Prompt 已经详细，先删掉冲突要求和冗余形容词；若结果偏离，补充最关键的缺失信息即可。
7. **独立资产优先**：每张图分别生成；不要将多个章节压进一张大图，不要把整页文章拼成图。
8. **记录失败并限制循环**：错误媒介、错字、关系错误、低清或构图失效的候选明确淘汰；默认一次初始生成 + 一次定向修订/重生成，仍失败就切换确定性图/表格/文字，不把失败候选写入正式资产目录。

## 7. 文字、流程和数据

- 概念图默认可以无文字；短标题/短标签可以尝试由模型绘制，但必须逐字核对。
- 中文长句、专业术语、数字、单位、图表轴、脚注和精确节点文案，先缩短为图内必要内容并写入逻辑 brief；模型可绘制短标签，但必须逐字校验，长解释移回正文/图注。
- 对简单流程图/关系图，直接把节点顺序和关系写进 Prompt，跳过 SVG；复杂图先冻结结构化逻辑源，必要时才用 SVG/Mermaid/HTML 作中间参考，再交给模型生成视觉图。模型不能改变节点全集、箭头方向、分支条件、因果关系和回路。
- 对数据图，数值、坐标和图形必须从真实数据确定性生成。模型不能生成或补齐数据。
- 如果模型输出的文字或关系有任何错误，不直接采用；先做一次局部定向修订，仍错误则用 SVG/HTML 重新排版准确内容或改用正文表格/文字，不连续重生成。

## 8. 交付与引用

- 原始候选放在 Git 忽略的 build 工作目录；只把选定最终资产写入 assets/images/blog/<slug>/。
- 不覆盖已有资产，除非用户明确要求替换；普通迭代先在工作目录生成，再选择性覆盖同一路径。
- 正式资产必须记录实际工具、Prompt/制作说明、像素尺寸、格式、文件大小、alt、caption 和来源/许可。
- 预览和正式发布继续遵守 VISUAL_GUIDE.md、IMAGE_GENERATION_WORKFLOW.md、WRITING_GUIDE.md 与 Preview Release Spec。
- 不能证明文件已写入仓库时，不得说“已入库”；不能证明网页已部署和显示时，不得说“在线可见”。
