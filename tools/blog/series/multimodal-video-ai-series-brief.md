## 二、系列运行方式：无总控、无 Handoff

本系列不再依赖一个长期“总控会话”，也不要求每篇完成后人工生成 `Series Handoff`。

**稳定事实只保留在两个地方：**

1. **本 Series Brief**：保存系列初始目标、候选文章和跨篇边界；
2. **GitHub / 正式网站**：保存已经完成并发布的文章事实、metadata、正文和显式文章关系。

每一篇新文章都单独新开一个会话。新会话首先读取本 Series Brief 和最新项目规范，然后主动读取 GitHub 与正式网站，重新构建“当前系列状态”。

因此：

- 不把上一个聊天会话的临时讨论当成必须继承的状态；
- 不需要用户人工复制上一轮总结；
- 不需要为了维持连续性更新 Series Brief v2 / v3；
- 未发布的临时规划不是系列事实，新会话应根据已发布内容重新判断；
- 如果新研究推翻旧规划，可以直接调整后续候选，不要求维持最初五篇。

### 当前系列状态的事实源优先级

判断已完成文章、历史观点、文章关系和发布状态时：

1. 当前线上正式发布页面；
2. GitHub `tools/blog/posts/<slug>.html`；
3. GitHub `tools/blog/data/posts-meta.json`（metadata 与 `relations`）；
4. `docs/blog/<slug>.md`；
5. 本 Series Brief 中的候选规划。

Series Brief 是**规划基线**，不能覆盖已经发布的事实。

### 3. 重新判断“下一篇是否仍值得写”

不要因为 Series Brief 写着“第 02 / 03 / 04 篇”就默认继续。

在进入实质探讨前，先检查：

- 这篇的核心问题是否仍独立成立；

### 4. 按最新 SOP 完成单篇文章

## 四、文章关系与“系列”不是同一概念

本系列属于**编辑层研究规划**，网站 `relations` 属于**发布层强文章关系**，两者不能自动等同。

同属本系列，不代表必须存在：

- `builds_on`
- `revises`
- `companion`

是否建立显式 relation，必须根据正文实际关系单独判断：

- **builds_on**：新文确实建立在旧文必要前提上，或继续推进旧问题；
- **revises**：新文实质修正、挑战或重新限定旧判断；
- **companion**：两篇回答直接互补的问题，共同阅读价值明显高于普通同主题。

正文历史内链也不自动产生 relation。

因此，本系列不需要额外增加 `series` metadata 才能推进写作；是否未来建设专题/系列前台展示，等实际形成多个成熟系列后另行决策。

### 01｜多模态到底统一了什么？

**分类：技术**

**状态：已正式发布。2026-09 已核验 GitHub `posts-meta.json` 与发布 HTML；后续仍以 GitHub / 正式网站为准。**

**文章角色：技术认知地基**

**最终核心问题：**

当一个 AI 产品可以处理文字、图片、声音和视频时，哪些能力属于多模态理解，哪些属于多模态生成；不同信息怎样从各自处理逐渐进入共同理解；用户看到的统一体验又有多少来自单一模型、多少来自系统层组合？

**最终核心结论：**

- 多模态理解与多模态生成是两种不同能力，不能因为产品能看图或能生成图片就混成同一种“多模态能力”；
- 模型内部可以呈现“输入先专业化 → 中间共同理解 → 输出再次专业化”，端到端统一与内部专业分工并不矛盾；
- 产品支持某种模态，不等于主模型原生支持该模态；本文将多个模型、工具或组件共同形成统一体验的形态称为“系统层多模态”；
- 本篇最终判断：**多模态真正统一的，未必是所有数据形式、模型和处理路径，而是不同类型的信息能够更直接地参与同一个任务。**

**已采用的关键案例：**

GPT-4o、Qwen2.5-Omni、DeepSeek V4 Flash Vision / DeepSeek-OCR、GPT-5.6 Sol + GPT Image 2、Claude、Sora、Seedance 2.5。

**对后续文章形成的稳定边界：**

- 不把 `Native / Omni / Unified` 当作一套固定、互斥的行业分类；看到厂商命名时继续拆成“能理解什么、能原生生成什么、模型内还是系统层组合”三个问题；
- 第 02 篇不再重新科普模态定义、理解 vs 生成、模型内统一 vs 系统层多模态，只承接最低必要前提；
- 第 02 篇应聚焦视频生成端为何仍然专业，以及视频模型的能力进步到底发生在空间质量、时间一致性、身份/状态保持、运动与物理、音视频协同、参考控制、编辑、长叙事和生产可用性中的哪些部分；
- 第 01 篇不建立与既有历史博客的强 `relations`；2026-09 核验时 GitHub 当前 metadata 为 `relations: []`，后续仍以最新发布事实为准。

### 02｜视频模型到底在进化什么？为什么“画面惊艳”已经不够了

**分类：技术**

**状态：已正式发布。2026-09 已核验 GitHub `posts-meta.json` 与发布 HTML；后续仍以 GitHub / 正式网站为准。**

**文章角色：核心视频专题**

**核心问题：**

为什么评价视频模型已经不能只看“画面是否惊艳”，以及视频生成从早期 Text-to-Video 到当前阶段真正解决了哪些新的问题？

**发布前研究方向（保留作规划记录，正式结论以发布文章为准）：**

- 视频为什么比静态图片生成更复杂；
- 空间质量、时间一致性、身份一致性、运动、物理合理性、镜头和声音；
- Transformer、Diffusion / Flow 的层级关系；
- Reference、Editing、Audio-Video Joint Generation；
- Sora、Kling、Veo、Runway、Seedance 等关键能力节点；
- 从 Demo Quality 到 Production Quality 的判断是否成立；
- 可控性是否只是 Production Quality 的一个组成部分。

**明确不展开：**

- 多模态基础重新科普；
- 基础模型公司与应用层最终谁赢；
- 视频生成是否已经等于世界模型；
- 广告、Agency、明星 IP 的完整产业重构。

### 05｜当 AI 让拍电影变快、变便宜，电影工业会先改变什么？

**标题状态：作者已完成稿的当前题名，不作为已发布标题。**

**分类：以正式稿及发布核验结果为准，不在本次规划调整中重新定类。**

**状态：按作者在本会话中的确认，已完成研究与写作、待发布。2026-09-13 本轮读取的 GitHub metadata 未出现对应条目，不记作已正式发布；下次启动须重新核验正式网站与发布 HTML。**

**以下保留原研究规划，不用它覆盖已完成稿或未来正式发布的正文。系列下一候选改为原第 04 篇。**

**文章角色：视频生产能力商品化之后的价值与稀缺性专题**

**核心问题：**

> 当 AI 开始接管从故事、分镜、预演、视频生成到剪辑的越来越完整制作链，电影制作能力本身持续变便宜以后，真正稀缺的会转移到哪里？明星、导演、IP、审美、身份授权、真实制作与观众体验分别会发生什么变化？

**作者真实触发：**

- 最近观看 Christopher Nolan 的《奥德赛》后受到很大震撼；
- 因此开始反向思考：如果未来 AI 可以生成这种级别的电影，今天电影中真正有价值、真正稀缺的部分到底是什么；
- 这只是作者第一手问题触发，不预设“AI 一定会复制《奥德赛》”或“真人电影会被取代”。

**当前候选研究方向：**

1. 《奥德赛》这类高成本、强真人制作、强导演作者性的电影，今天真正让观众付费和感到震撼的到底是什么；
2. AI 视频生产降低的究竟是哪些成本：执行、拍摄、VFX、预演、素材生产、剪辑，还是更多；
3. 当普通视觉生产越来越便宜后，“真实拍摄 / 真人表演 / 实体场景 / 导演作者性”是否可能反而产生新的稀缺溢价；
4. 真人明星的价值是否会部分从有限档期和一次性现场劳动，转向 likeness / voice / persona / digital replica 等身份与授权资产；
5. Digital Replica、Synthetic Performer、AI 原生演员与传统明星之间未来可能是什么关系；
6. AI 原生“明星”究竟更像演员，还是更像持续运营的角色 / IP；
7. Agent 化影视制作是否正在把“执行能力”和“创作判断”进一步拆开；
8. Agency / 制作公司的价值是否会从制作资源向创意判断、IP、客户理解和商业结果移动；
9. 生产成本下降以后，导演、明星、IP、审美、分发、品牌信任、影院体验中哪些会变得更加稀缺；
10. 最强反例：AI 制作越来越便宜，不等于真人电影、真人明星、线下影院体验的价值会线性下降。

**候选现实信号（待正式研究核验）：**

用户提供的“GPT-6 Astra + Seedance 2.5”材料，当前只标记为 **Agent 化影视制作链的早期现实信号 / 从业者实验案例**。案例展示的候选信号包括：

- 人类只给一个总体 Brief；
- GPT-6 Astra 自行写故事；
- 在 Blender 中完成 Previs / 3D Blockout；
- 安排角色、场景、机位和镜头；
- 生成关键帧 / 参考帧；
- 调用 Seedance 2.5 生成正式视频镜头；
- 再进入剪辑工具完成时间线、剪辑和导出；
- 另一个 DaVinci 调色案例显示，AI 可以完成技术操作，但网友对最终审美结果明显存在分歧。

这组材料主要用于提出问题：**当执行链越来越能被 Agent 接管以后，价值会不会进一步向创作目标、Taste、IP、身份资产和最终判断迁移？**

不得把该案例升级成“电影工业已经完成自动化”“GPT-6 已经可以独立导演电影”“Seedance 已经能生产工业级长片”或“AI 已经解决审美判断”的结论。

**与其他系列文章的边界：**

- **与第 02 篇：**第 02 篇研究视频模型本身怎样从画质、一致性、状态保持走向参考、控制、编辑、Agent 化创作流程和生产可用性；本篇研究这些生产能力持续商品化以后，电影产业中的价值和稀缺性如何重新分配，不重新完整科普视频模型能力史。

**当前研究边界：**

本篇当前不预设：

- AI 最终一定取代真人电影；

- 只要视频模型能力足够强，导演 / Agency / 制作公司就会消失；
- “真实拍摄”一定会成为奢侈品或高端标签。

这些判断都必须在正式研究中验证。暂时不展开完整版权法史、工会规则史或电影发行制度史，除非它们直接影响“新的稀缺资源是什么”这一核心判断。

## 六、共享概念账本

以下均为**当前工作口径**，不能覆盖后续单篇研究结论。

### Multimodal Understanding
模型能够接收并理解来自多个模态的信息。

### Multimodal Generation
模型能够直接生成一种或多种模态输出。

### Native / Omni Multimodal
不是本文采用的一套固定行业分类。厂商使用 `Native`、`Omni`、`Unified` 等命名时，后续文章不根据名称直接推断架构，而继续拆成三个问题：模型能理解哪些模态、能原生生成什么模态、这些能力由一个模型内部完成还是由系统组合完成。

### System-level Multimodality
第 01 篇采用的工作定义：一个产品由多个模型、工具或组件共同提供统一的多模态体验。它与“模型内统一”可以同时存在，不是厂商统一使用的官方架构术语。

### 前分—中合—后分
第 01 篇形成的认知模型：不同模态在输入端可以保留专业处理，中间进入共同上下文并参与共同理解与推理，输出端再根据任务继续由模型内部专业生成或调用系统中的专业模型。它是帮助理解的简化地图，不是行业统一架构。

### Production Quality
当前候选工作定义：视频不仅单个 Demo 看起来好，还能够稳定按照创作者意图进行控制、修改、保持一致并进入真实生产流程。

是否采用该术语由第 02 篇决定。

### World Model
暂不预设唯一行业定义。

第 04 篇需要区分世界状态预测、action-conditioned prediction、interactive world model，以及用于规划和机器控制的世界模型。

## 七、跨篇共同原则

### 每篇必须先独立成立
不能因为 Series Brief 里已经排好顺序，就把后一篇写成前一篇的机械续集。

### GitHub 已发布事实高于系列规划
如果已发布文章已经覆盖某个候选问题，下一篇必须重新判断增量，而不是照原计划继续。

### 不重复完整框架
旧文已经完整解释的内容，采用“最低必要前提 + 正文链接 + 新增判断”。

### 前文结论可以被后文推翻
发现新证据时允许修正，而不是为了保持系列一致维护旧判断。

### 新材料优先进入研究树
新案例、新厂商或更宏大的问题优先归入核心证据、反证/边界、背景或后续分支；只有真正推翻当前核心机制才重新打开单篇主线。

### 系列不是发布层强关系
是否有正文内链、`relations` 或未来专题 UI，分别按各自规则判断，不为了“系列感”强行建立。

## 十、Series Brief 的更新与删除

正常情况下，**不因每完成一篇就更新本文件**。

- 系列的研究主线、候选优先级或实际研究顺序发生实质变化；
