## 二、系列运行方式：无总控、无 Handoff

本系列不再依赖一个长期“总控会话”，也不要求每篇完成后人工生成 `Series Handoff`。

**稳定事实只保留在两个地方：**

1. **本 Series Brief**：保存系列初始目标、候选文章和跨篇边界；
2. **GitHub / 正式网站**：保存已经完成并发布的文章事实、metadata、正文和显式文章关系。

每一篇新文章都单独新开一个会话。新会话首先读取本 Series Brief 和最新项目规范，然后主动读取 GitHub 与正式网站，重新构建“当前系列状态”。

因此：

- 不把上一个聊天会话的临时讨论当成必须继承的状态；
- 不需要用户人工复制上一轮总结；
- 不需要为了维持连续性更新 Series Brief v2 / v3；
- 未发布的临时规划不是系列事实，新会话应根据已发布内容重新判断；
- 如果新研究推翻旧规划，可以直接调整后续候选，不要求维持最初五篇。

### 当前系列状态的事实源优先级

判断已完成文章、历史观点、文章关系和发布状态时：

1. 当前线上正式发布页面；
2. GitHub `tools/blog/posts/<slug>.html`；
3. GitHub `tools/blog/data/posts-meta.json`（metadata 与 `relations`）；
4. `docs/blog/<slug>.md`；
5. 本 Series Brief 中的候选规划。

Series Brief 是**规划基线**，不能覆盖已经发布的事实。

### 3. 重新判断“下一篇是否仍值得写”

不要因为 Series Brief 写着“第 02 / 03 / 04 篇”就默认继续。

在进入实质探讨前，先检查：

- 这篇的核心问题是否仍独立成立；

如规划需要变化，直接说明理由并给出当前推荐，不要求返回旧总控会话。

### 4. 按最新 SOP 完成单篇文章

单篇内部完整执行最新博客流程。当前基线包括但不限于：

## 四、文章关系与“系列”不是同一概念

本系列属于**编辑层研究规划**，网站 `relations` 属于**发布层强文章关系**，两者不能自动等同。

同属本系列，不代表必须存在：

- `builds_on`
- `revises`
- `companion`

是否建立显式 relation，必须根据正文实际关系单独判断：

- **builds_on**：新文确实建立在旧文必要前提上，或继续推进旧问题；
- **revises**：新文实质修正、挑战或重新限定旧判断；
- **companion**：两篇回答直接互补的问题，共同阅读价值明显高于普通同主题。

正文历史内链也不自动产生 relation。

因此，本系列不需要额外增加 `series` metadata 才能推进写作；是否未来建设专题/系列前台展示，等实际形成多个成熟系列后另行决策。

### 01｜多模态到底统一了什么？

**分类：技术**

**状态：已正式发布。2026-09 已核验 GitHub `posts-meta.json` 与发布 HTML；后续仍以 GitHub / 正式网站为准。**

**文章角色：技术认知地基**

**最终核心问题：**

当一个 AI 产品可以处理文字、图片、声音和视频时，哪些能力属于多模态理解，哪些属于多模态生成；不同信息怎样从各自处理逐渐进入共同理解；用户看到的统一体验又有多少来自单一模型、多少来自系统层组合？

**最终核心结论：**

- 多模态理解与多模态生成是两种不同能力，不能因为产品能看图或能生成图片就混成同一种“多模态能力”；
- 模型内部可以呈现“输入先专业化 → 中间共同理解 → 输出再次专业化”，端到端统一与内部专业分工并不矛盾；
- 产品支持某种模态，不等于主模型原生支持该模态；本文将多个模型、工具或组件共同形成统一体验的形态称为“系统层多模态”；
- 本篇最终判断：**多模态真正统一的，未必是所有数据形式、模型和处理路径，而是不同类型的信息能够更直接地参与同一个任务。**

**已采用的关键案例：**

GPT-4o、Qwen2.5-Omni、DeepSeek V4 Flash Vision / DeepSeek-OCR、GPT-5.6 Sol + GPT Image 2、Claude、Sora、Seedance 2.5。

**对后续文章形成的稳定边界：**

- 不把 `Native / Omni / Unified` 当作一套固定、互斥的行业分类；看到厂商命名时继续拆成“能理解什么、能原生生成什么、模型内还是系统层组合”三个问题；
- 第 02 篇不再重新科普模态定义、理解 vs 生成、模型内统一 vs 系统层多模态，只承接最低必要前提；
- 第 02 篇应聚焦视频生成端为何仍然专业，以及视频模型的能力进步到底发生在空间质量、时间一致性、身份/状态保持、运动与物理、音视频协同、参考控制、编辑、长叙事和生产可用性中的哪些部分；
- 第 01 篇不建立与既有历史博客的强 `relations`；2026-09 核验时 GitHub 当前 metadata 为 `relations: []`，后续仍以最新发布事实为准。

### 02｜视频模型到底在进化什么？为什么“画面惊艳”已经不够了

**分类：技术**

**状态：已正式发布。2026-09 已核验 GitHub `posts-meta.json` 与发布 HTML；后续仍以 GitHub / 正式网站为准。**

**文章角色：核心视频专题**

**核心问题：**

为什么评价视频模型已经不能只看“画面是否惊艳”，以及视频生成从早期 Text-to-Video 到当前阶段真正解决了哪些新的问题？

**发布前研究方向（保留作规划记录，正式结论以发布文章为准）：**

- 视频为什么比静态图片生成更复杂；
- 空间质量、时间一致性、身份一致性、运动、物理合理性、镜头和声音；
- Transformer、Diffusion / Flow 的层级关系；
- Reference、Editing、Audio-Video Joint Generation；
- Sora、Kling、Veo、Runway、Seedance 等关键能力节点；
- 从 Demo Quality 到 Production Quality 的判断是否成立；
- 可控性是否只是 Production Quality 的一个组成部分。

**明确不展开：**

- 多模态基础重新科普；
- 基础模型公司与应用层最终谁赢；
- 视频生成是否已经等于世界模型；
- 广告、Agency、明星 IP 的完整产业重构。

**核心问题：**
