# Blog Design — 博客视觉设计规范

本文件定义「思考碎片」博客在文章页和列表页的视觉与交互规范，是 WRITING_GUIDE.md 的补充。新文章参照本规范执行；存量文章不强制回改。

## 继续阅读与时间导航

- 正文末尾的「继续阅读」是克制的文字列表，默认约 3 项；存在 4 个已确认的显式强关系时允许展示 4 项。自动同主题只负责补足默认目标，不为了凑数量增加页面密度；每项按弱到强的层级显示关系标签、可折行标题和日期。
- 标签只做轻量陶土色提示；「修正」不使用错误或警告视觉。链接在 hover 和 keyboard focus 时必须清晰可辨。
- 「上一篇 / 下一篇」保留为独立日期导航，视觉上以分隔线与继续阅读区分，不能混入关系标签。
- 手机端每项标签独占一行，标题和日期组成第二行；深色和浅色均使用文章页既有 CSS 变量。

## 一、文章页：正文段落节奏

**问题：** 正文 `<p>` 间距默认 `margin-bottom: 16px`，连续多段密度高，长文容易视觉疲劳。

**规范：**
- 新文章的 `<style>` 中将 `.post-body p` 的 `margin-bottom` 设为 `20px`
- 每隔 3-4 个普通段落，主动用 `<h2>` 开新节——避免无结构的长段堆叠
- 不要为了"填满"一节而在同一 h2 下堆超过 6 段正文

```css
/* 新文章 <style> 中覆盖默认值 */
.post-body p { margin-bottom: 20px; }
```

## 二、文章页：强调文本克制使用

**问题：** `<strong>` 出现频率过高时，所有重点等于没有重点。

**规范：**
- 每段最多 1 处 `<strong>`
- `<strong>` 只用于**核心判断句**，不用于修饰性词语、产品名、或引用来源
- 同一段内禁止连续出现 2 个以上 `<strong>`

**判断方法：** 把所有加粗文字单独列出来读，如果能形成文章的骨架提纲，则使用合理；如果只是随机强调，则过度。

---

## 三、文章页：decision-card 组件规范

**问题：** 连续 3 个 decision-card 视觉等权重，缺乏呼吸感。

**规范：**
- decision-card 之间 `margin` 用 `24px`（模板默认 `20px` 稍紧，新文章覆盖）
- decision-card 内正文 `<p>` 字号 `13px`，颜色 `var(--text-2)`，不要在卡片内再用 `<strong>`
- 文章若有 3 个以上 decision-card，必须用 `<h2>` 节标题将它们包在同一节下，不要在不同节里各散放 1 个

```css
/* 新文章覆盖 */
.decision-card { margin: 24px 0; }
```

### level-card 使用边界

`level-card` 用于 2–4 个互斥层级或阶段的并列解释，例如「工作流 / 伪智能体 / 真智能体」。它不是正文段落容器：每项只保留层级标签、短标题和一段说明；普通论述、引用、参考资料和单句结论不做卡片，也不嵌套卡片。文章需要一条可带走的结论时，使用 `callout` 而不是新增卡片。

---

## 四、文章页：callout 块内容密度

**规范：**
- callout 内正文不超过 3 句话；超过时将多余内容移回正文节，callout 只留核心结论
- 新文章写完后，在深色主题下截图检查一次 callout 背景对比度（clay-soft 在深色下较淡）
- callout 内禁止嵌套列表或子标题，保持单一文字块

---

## 五、文章页：参考资料节

**规范：**
- 参考资料是全文末尾的辅助信息层，不与正文、callout 或「继续阅读」争夺相同的字号和视觉重量；默认收起为“参考资料 · 展开 N 条来源”，不截断、不删除来源。读者点击或按键展开，且从目录或 URL 锚点跳至该标题时自动展开；这样「继续阅读」始终在首屏后的自然阅读路径中可见。
- 统一以 13px 的 `参考资料` 标签、12px 的分组标题/来源行/可信度说明、1.6 行高和 6px 来源行节奏呈现；两种主题均使用低于正文、但满足对比度的 `--text-2`。来源链接仅在 hover 或键盘焦点时转为陶土色并显示下划线。
- 区块以一条细分隔线与正文分开；可信度说明在来源列表后以自己的细分隔线开始。这个紧凑比例以 `llm-reshapes-software-roles.html` 为基线，正文正文字号不随之缩小。
- 参考资料链接数量建议 ≤ 12 条；超过时按来源性质或论证部分做有意义的内部分组。
- 不要在单篇文章复制 `.refs` 样式。`article-runtime.js` 会同时处理历史 `.refs` 容器和 Markdown 生成的 `h2`/`h3`/列表结构，并使用文章已有的浅深色 token。

```html
<h2 id="references">参考资料</h2>
<h3>产品发布相关</h3>
<ul><li><a href="...">...</a></li></ul>
<p><strong>来源可信度说明：</strong>说明样本、转述或适用边界。</p>
```

## 六、文章页：h2 密度与 TOC

**规范：**

| h2 数量 | 处理方式 |
|---------|---------|
| ≤ 2 个 | 不加 TOC，单栏布局 |
| 3-6 个 | 标准双栏布局 + 左侧 toc-card |
| ≥ 7 个 | 考虑拆成两篇，或将部分 h2 降为加粗段落 |

- 每个 h2 节下的正文建议 200-500 字（约 1-4 段）
- 避免一个 h2 下只有 1 段（太短，不值得单独成节），或超过 8 段（太长，应再分节）

## 列表页：精选文章

- 精选是作者手动维护的展示层，不是按发布时间、阅读量、文章关系或搜索结果自动计算的推荐。
- 首页保持三篇文章：第一篇为 `featured-posts.json` 的首个有效 slug，后两篇由 metadata 中的最新非重复文章自动补齐；无有效精选时退化为最新三篇。
- Blog 默认页只在「全部、无搜索、第 1 页」显示「精选阅读」，最多展示配置中的前三篇。当前配置不足三篇时保留空缺，不为了视觉完整补内容。
- 精选区复用列表行、日期、摘要和标签结构，只增加轻量「精选」标签；不使用大卡片、封面图、轮播或 Hero。
- 默认时间流排除已显示精选，保证不重复；分类、搜索和后续分页隐藏精选区，并恢复精选文章在完整时间流中的正常位置。
- 浅色、深色和移动端均沿用列表页既有 token、单栏与换行规则，精选标签不得抢占标题层级。

## 七、列表页：年月分组

**现状（问题）：** JS 按年份分组（取 `date.split('.')[0]`），13 篇文章全堆在"2026"一组，年份分组失去时间线导航价值。

**规范（目标状态）：** 按 `YYYY.MM` 分组，`year-label` 显示"2026 · 04"。

**实现（`index.html` JS `render()` 函数）：**

```js
// 改为按 date 全字段分组（YYYY.MM）
var byYM = {};
list.forEach(function (p) {
    var ym = p.date; // 直接用 "2026.04"
    if (!byYM[ym]) byYM[ym] = [];
    byYM[ym].push(p);
});
// year-label 显示格式："2026 · 04"
var label = ym.replace('.', ' · ');
```

## 八、列表页：摘要展示方式

**结论：摘要保持静态展示（始终可见），不做 hover 折叠。**

hover 折叠动效在实际使用中体验较差：鼠标滑过列表时内容持续跳动，反而影响阅读效率。摘要的价值在于帮助快速判断是否值得点进去，静态展示更直接。

如文章数量增多（> 30 篇）导致列表过长，优先考虑分页方案（见 WRITING_GUIDE.md"未来考虑"节），而非折叠摘要。

## 十、列表页：搜索与分类状态独立

**现状（问题）：** 搜索词和分类切换之间没有视觉反馈，用户不清楚当前同时生效了哪些过滤条件。

**规范（目标状态）：** 两者状态独立维护（已是），但在搜索框下方展示当前生效的过滤条件 chip。

**实现要点：**
- 搜索框和分类按钮互不清空对方（已实现，维持现状）
- 在 `.search-box` 下方追加 `#activeFilters` 容器，当 `cat !== 'all'` 或 `query` 非空时显示对应 chip
- chip 带 `×` 按钮，点击清除对应条件并重渲染
