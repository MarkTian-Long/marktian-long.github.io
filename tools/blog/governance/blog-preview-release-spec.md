# 发布级图文预览与确认后发布

版本：1.1｜更新：2026-11-08

本文件是 Blog SOP 的阶段补充：管理正文讨论结束后，用户要求“插图、看全局预览”时的交付标准，以及用户确认后的发布切换。写作、事实、图表语义、图片制作和网站发布契约仍分别由现有规范维护，不在这里复制细则。

## 1. 触发与质量边界

用户在正文讨论后要求插图、完整 H5 或全局预览时，默认进入“待发布审阅稿”，不再交付另一套简化样式的演示页面。预览按正式发布要求处理正文、引用、加粗、图片、阅读体验和内容元数据；未正式发布只是一种分发状态，不是降低质量的理由。

用户明确要求看概念草图、原始初稿或局部方案时，可以交付探索候选，但必须标明它不是已写入文章的成品。聊天中生成一张图片，不代表网页已经替换。

## 2. 用户审阅前完成什么

- 以唯一 Markdown 当前稿为源，完成活人感审校、Checklist 适用项和修改后的回归检查。按 SOP 标出独立推理链的结论落点，不机械增加加粗数量。
- 配图完成选用、逐字与语义校验、实际资产写入、alt/caption 对齐及页面渲染。生成式候选、确定性图源、最终展示资产分别标明；不拿候选冒充上线成品。
- 采用正式文章模板和共享运行时、链接样式、主题、目录、参考资料呈现。不得手写另一套相近 CSS 后称为“完全同款”；尤其检查运行时动态加载的样式，而不只看模板中的内联 CSS。
- 按当前 taxonomy 准备 category、tags、topics、concepts、share_quote、relations。词典缺口可按已有规则记录暂缺，不能造词或选近似词凑数；不把作者审批与自动校验混为一谈。
- 对最终稿对应的实际 HTML，完成桌面、手机和深浅主题验收。核对文字大小、箭头端点、分支标签、图片截断、页面溢出、链接颜色与图文位置；不能用 CI 通过替代视觉检查，也不能让手机读者必须横向拖动才能理解主结论。

## 3. 单一来源与预览地址

未发布正文仍维护在 `drafts/blog/<slug>.md`；预览使用稳定的 `tools/blog/previews/<slug>.html` 或网站明确支持的等价隔离路径。`?v=<commit>` 只用于刷新缓存，不是草稿与正式稿的隔离机制，不创建多个实际生效的预览副本。

预览设置 noindex，保留一处简短“审阅预览／未发布”提示；不写虚构发布日期，不提前进入正式文章索引、搜索、RSS、sitemap 或推荐关系索引。公开预览并不私密，知道链接的人仍可访问。

预览应由同一正文、已选图源与正式模板派生。优先复用正式生成器；若现有生成器尚不支持未发布 metadata，使用适配层并明确实现边界，禁止声称已经具备自动发布切换。适配层不得另行改写正文或维护第二套设计规则。

预览需要独立图片时，只允许显式登记必要资产路径，不把整个 drafts 目录加入公开产物。源稿和内部审查记录不进入 Pages 产物。

## 4. 用户确认后的发布切换

用户明确确认正式发布后，再执行以下确定性操作，不重写已确认正文或擅自换图：

1. 记录用户确认所对应的 Git commit。把唯一 Markdown 当前稿迁移到 `docs/blog/<slug>.md`，按正式契约迁移并登记已确认的图片资产；不保留两份可编辑正文。
2. 同步正式 posts-meta、文章 HTML、canonical、分享地址、文章关系、搜索、RSS 和 sitemap；图片及内链使用正式路径。
3. 将旧预览地址重定向或明确指向正式文章，避免两份正文继续独立演化。保留必要锚点；静态页面跳转不是服务器 HTTP 301，报告中不得混称。
4. 运行下述确认稿一致性检查，再运行标准校验、构建与部署，回读提交，并检查正式 URL、图片和关键链接。发布端不再自行决定内容分类、补写观点或更换引用。
5. 正文、资产、索引、正式页面和旧预览跳转尽量在同一提交切换；从公共白名单移除旧 draft 图片路径，不将整个草稿目录公开。

### 确认稿一致性检查

对采用本规范草稿路径的文章，在发布工作区运行：

```sh
node scripts/check-blog-release-equivalence.js --approved-ref <已确认稿的完整40位commit> --slug <slug>
node --test scripts/blog-release-equivalence.test.js
```

检查器从已确认 commit 读取草稿及图片，与当前 `docs/blog/<slug>.md` 和正式图片对比；只允许换行符规范化和规定的图片相对路径迁移。正文、引用、语义字段、加粗、图注或图片字节变化都会阻止通过。输出源稿与图片哈希，作为同一确认版本的证据，不创建第二份正文。

浅克隆缺少确认 commit 时，应按仓库权限取得该明确版本；不能跳过检查或拿最新主分支冒充作者已确认版本。不同路径或新增封面等现有检查器未覆盖的情况，须显式记录差异并人工核准，不扩大允许变化范围来让检查变绿。检查器不评价事实正确、美观或可读性，也不替代正式生成器、图片契约、taxonomy、SEO 和浏览器验收。

因此，用户体验上应接近“确认后切换为正式文章”，但实现不能仅改文件名或 URL 后缀。不得为单篇文章修改 Pages 工作流权限或塞入远端写仓库逻辑。现有生成器仍未提供通用的一键预览晋升命令；本检查器只验证同稿迁移，不自动发布。

## 5. 状态报告

交付只区分已经完成的环节：内容审校、资产选定、仓库写入、构建部署、线上访问、视觉验收、作者批准、正式发布。每项结论对应实际检查对象与证据；不得把创建 blob 当成文件已更新，把部署成功当成浏览器已验收，把离线渲染当成线上截图。

记录页面、commit／源稿哈希、图片路径、视口、主题和检查范围。离线渲染若未执行共享运行时，只证明当次图文与样式，不证明在线链接、目录、分享或推荐交互；这些功能必须由实际页面或标准浏览器测试另行核对。来源事实复核也与视觉验收分开记录。

若当前环境缺少某项能力，集中说明真实缺口，不以反复输出相同检查日志或不断换图延长用户确认。CI 未结束时只报告当前状态；取得新证据后再更新状态，不提前声称成功。

本规范只把验收前移，不新增逐张图或逐条样式的审批轮次，也不取消作者最后的正式发布确认。不因本篇选择取消“结语”或采用四张图，就建立跨文章的固定格式配额。
