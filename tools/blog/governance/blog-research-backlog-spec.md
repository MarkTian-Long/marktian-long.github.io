# Blog 研究待办维护规范

版本：1.3｜更新：2026-11-08

## 职责与入口

本规范只管研究记录的结构、编号、日期、原位更新和整理验收；记录文件为 [research_backlog.md](../research_backlog.md)。何时收录、如何召回与聚合、状态定义、立项门槛和正式写作流程，继续以 [Blog SOP](blog-sop.md) 的“研究待办记录与跨事项聚合”为准。本文件是其记录维护细则，不另建一套研究或写作流程；发生实质流程变化应修改 SOP，而不是在这里覆盖它。

从 [治理入口](README.md) 进入。一个用途一个当前真源：本文件不保存选题，记录文件不复制通用规范；不为每条新闻建文件，也不新增待办 Skill。网站开发待办仍在原 TODO，系列规划仍在 Series Brief，完整文章进入既有工作稿流程。

## 一、记录文件的四层结构

1. **研究总览**：一条事项一行，显示可点击的问题名、创建日期、状态及最关键的下一步。状态后用短括号标出成文边界或实际转入阶段；最后一列采用“责任方：动作／阻塞”的写法，使读者能直接看出是 AI 继续研究、作者确认方向、需要实测，还是等待外部信息。最近明确讨论的事项可以前置；**总览的阅读顺序不代表下一篇优先级**，创建日期与 ID 也不代表先后排期。用户要求选题排序时按 SOP 当轮比较，标明评估日期、推荐理由和老卡为何暂未优先；除非用户明确要求保存排期，不在总览维护一份会迅速过期的固定排行榜。完整 ID 放研究卡，避免编号占据总览的主要宽度。
2. **当前研究卡**：每个稳定 ID 只维护一份当前判断。固定字段为“创建与更新 / 核心问题与用户重点 / 当前判断 / 关键证据与反证 / 成文边界与缺口 / 下一步与责任 / 关联与去向”。已有卡可将后两个执行字段合并，不为凑模板机械拆段。简短摘要默认展开；详细来源、较长比较和未执行的研究方案放同卡的 details 折叠区。折叠只减少阅读负担，不改变证据等级。
3. **跨事项聚合候选**：仅保存多个独立问题之间尚待验证的连接关系，写清关联 ID、各自角色、共同问题与缺口。不复制事项卡的完整主线、资料和研究方案。一个事项加若干辅助材料，不需要再建一个同名聚合候选。
4. **关键决策与结项**：保留方向变化、拆分、合并、转入和关闭的日期、理由及去向。详细旧版本由 Git 历史承接，不把多轮聊天全文叠进当前卡。

状态使用 SOP 的六种当前值：**待研究 / 待关键补证 / 可进大纲 / 已转入 / 已合并 / 已关闭**。旧称“待补证／可立项”只在历史决策与 Git 记录中保留，不作为新记录状态。不新增 A/B/C、“补证完成”“已确认选题”等平行状态。下列要求用于检查记录是否把 SOP 的研究判断写清，而不是替代其成文门槛。

### 成文边界与缺口的填写

每张活跃研究卡应能回答三个问题：**目前可以写到哪里；什么缺口会改变核心判断；下一步是谁做什么。**

- **成文边界**：给出一句可承载的问题或主张，并说明不能据此推导什么。可进大纲不要求所有未知消失，也不表示正式标题、分类或大纲已经确认。
- **阻断缺口**：缺少它就无法建立主要事实、因果链或独立内容增量。标记待关键补证时必须写明这个缺口，不能只写“还需要更多案例”。若收窄主张能消除阻塞，同时记录可写的范围和被排除的结论，不能暗中更换作者关心的问题。
- **非阻断补证**：更多案例、精确日期和参数、局部解释、后续商业结果，或已明确排除在当前主张之外的验证。此类工作可以在探讨和写作中继续；不能仅因存在这些缺口就让已经可进大纲的题目长期停留在待关键补证。
- **已转入的实际阶段**：写明“系列研究分支 / 写作中 / 已发布”等真实去向及链接。发现完整工作稿不等于已经终审通过，文章发表也不等于研究假设全部得到验证。已转入条目的后续证据不重新计作一篇待写文章。

### 下一步与责任的填写

使用业务含义明确的短语，不另建负责人状态机：

- **AI 公开补证**：公开来源核验、原论文与官方文档、反例、机制对照、历史正文碰撞检查。具体写要解决的未知，不把公开检索任务默认交给作者。
- **作者确认**：仅用于真实经历、不可公开业务事实、作者立场，以及正式范围、分类和大纲。不得因缺少普通公开资料而笼统标记“等用户”。
- **需实测**：写清要验证的命题、访问／数据／设备条件，以及该实测是否阻碍当前限定范围成文。没有实际访问或执行，不得记录为完成；不能默认作者接受付费、安装或生产环境测试。
- **待外部**：写清等待什么可观察信息，例如正式上线、真实订单、同口径数据、当事方说明或长期追踪。搜索未找到不等于信息不存在；记录本轮检索边界和下次重访的证据触发，不承诺未经设置的后台监控。
- **自动补证追踪**：当运行中的聊天／任务实际读到待研究或待关键补证卡，且存在可处理的公开缺口，按 SOP 主动核验，不必逐次询问；卡片记录**本轮核验完成到哪里、仍待何种新证据、下次触发条件**。公开搜索已无信息增量时应停止，不把“待关键补证”理解为持续运行的后台任务，也不把必须等未来结果的事项默认交给作者。

可有多个参与方，但须明确**当前下一步**由谁推进。作者的方向与大纲确认是写作流程的必要决策，不应被误写成“证据不足”。

### 批量补证的记录与验收

独立问题可以分批并行检索，最终由一次整合更新统一当前判断；不得并行覆盖同一路径。每项记录本轮获得的证据、改变或未改变的判断、仍未完成的验证及下一行动。资料访问失败、只有摘要、只有搜索索引、来源版本变化等限制应就近标明。

“本轮可独立执行的公开补证已完成”不等于“所有证据已齐”或“已完成真实实验”。收束时将结果落为：可在限定范围进入大纲、仍有具体阻断条件、转入既有主题、合并或关闭；不只汇报搜了多少条资料。若状态变化，同步总览和卡片标题下状态；历史决策中的旧称不必强行追改。对于不能由本轮公开检索消除的缺口，明确是实测、作者信息还是外部事实，避免下一会话重复无目标搜索。

## 二、编号与四种时间

- **稳定 ID**：新事项用 `BR-YYYYMMDD-NN`，日期是首次实际入库日，序号为当日递增号。旧 ID 不因更新、改标题或排序而重编，也不是优先级。无法确认历史创建日时标“未知 / 最早可核查于某日”，不推算、不伪造。
- **创建日期**：首次把该独立问题写入研究记录的日期。新闻发生、论文发表或用户首次产生想法的日期，不能替代它。
- **内容更新日期**：核心问题、判断、证据、缺口、下一步、状态或关联发生实质变化的日期；纯排版、移动段落、改链接显示文字不刷新各事项的内容日期。
- **证据核验日期**：实际查看并核对具体来源的日期，尽量跟随来源或材料组记录。核对仓库文件、调整题目、重新排版不等于重新核验外部原文。沿用旧摘录时注明“既有材料记录；本轮未重验”，不把所有来源统一刷成今天。
- **事件 / 触发日期**：另写在来源或触发说明中。动态文档无明确发布日期时如实标注；不要拿当前抓取日替代发布日期。全文件整理日期仅表示结构维护。

## 三、更新旧项还是新建事项

同一核心问题的新案例、反证、边界或局部改题，更新原 ID。出现可以独立回答的问题，并且研究对象、需要的证据或后续行动明显不同，才新建 ID 并链接来源事项；不能因为属于同一大主题而把新问题全部塞进旧条目，也不能因每轮有新闻而重复立项。

拆分时保留旧事项的有效范围，新卡承接被拆出的当前内容，不复制整份资料。历史上误并进旧项的新问题，可按首次实际记录日补立独立 ID，并在决策区说明原位置和迁移理由；不得回改旧事项创建日来掩盖历史。原问题全部被替代时按 SOP 合并或关闭；只有分支拆出时不误把原问题结项。

## 四、默认合并，不默认追加

每次更新先读 GitHub 当前卡与必要规范，再判断增量属于哪个字段。将新结论写回该字段，同步总览和有影响的关联；失效观点从当前摘要移走，只留“原判断 → 新判断 → 变化原因”的简短记录。不得连续堆叠“某日增量 / 再补充 / 追加收束”并让多个版本并列生效。

用户重点、真实反例、证据局限、关键缺口和判断变化理由必须保留。相同来源在主卡保存一次，其他卡用链接指向它；不同来源的相似内容可压缩，但不能把未读来源写成已核验、把发布说明改成采用证据、把研究设计写成已执行实验。通用的“未立项 / 未锁定分类 / 未批准大纲”在文件入口说明，单卡只补本条特有的授权或阶段差异。

## 五、安全回写与整理验收

写入前读取当前版本与 SHA；若工具返回截断内容，补齐需要保留的范围，不能用片段覆盖整份文件。对实质拆分建立旧位置到新 ID 的映射。若必须全文件替换，先检查与当前版本的差异，保留无关内容；发生版本冲突则重读并合并，不能强行覆盖。

完成前检查：ID 唯一且日期合理；总览与卡片一一对应；总览排列未被误标为已批准的研究优先级；较早但可进大纲的卡片在选题筛选时有合理的启动或暂缓解释（无实质变化不刷新内容日期）；状态、成文边界、阻断／非阻断缺口、责任方和关联一致；已转入条目附有实际阶段和去向；折叠区及内部锚点可用；无重复候选和并列旧结论；关键来源与边界没有丢失；本次未擅自写入文章 metadata、生成 relations、改 Series Brief 排期或发布文章。状态计数按独立研究卡计算，系列指针、后续证据和聚合观察不额外算作待写文章。回写后读取远端文件或校验 blob SHA，并报告实际文件、提交和主要决策。外部链接本轮未重验、未做完整运行测试等限制必须如实说明。
