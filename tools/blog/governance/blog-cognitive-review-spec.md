# 认知增量反馈与章节结构验收

版本：1.3｜更新：2026-11-22

本文件补充 Blog SOP 的阶段交付，不另建研究方法、评分体系或独立流程路由。写作前反馈是否构成必经作者确认关口，由项目指令和 Blog SOP 决定；本文件定义各检查时点的内容、证据边界与结构验收方法。适用于从研究待办、系列、新闻链接、聊天兴趣点等入口正式启动的博客。既有 SOP 的研究深度与问题重构、Checklist 的章节贡献与推断层级仍是内容依据。

## 1. 三个检查时点，两个独立作者关口

- **大纲确认前预检（研究成熟度判断）**：沿用 SOP 的独立起点快照和研究深度检查，判断预期增量是否足以支持进入大纲。它属于研究收敛，不是作者审批；成熟后交付完整大纲确认稿，尚有阻塞则说明具体缺口。
- **大纲确认后、正文写作前反馈（独立作者确认关口）**：作者明确确认完整大纲后、内部完整初稿开始前，必须单独交付写作前认知增量反馈，并取得作者明确确认。它不等同于大纲里的研究增量摘要，也不等同于正文完成后的认知验收；分类确认或大纲确认不能替代它。详细内容见第 3 节。
- **图文一体成稿阶段内的正文完成后、首次完整图文预览前验收（正文质量验收）**：完整正文完成、活人感审校和 Checklist 当前内容阶段适用项通过后，必须在当前对话向作者交付正文实际承载的认知增量、章节关系图/表与剩余边界。Checklist 全量扫描中依赖本报告实际交付、页面或正式发布的项仍为待验，不能提前宣称全部通过。首次预览链接前必须可见地反馈，不能等到图文预览已经交付或正式发布之后才补报；之后按依赖完成页面及发布阶段的检查。
- 写作前反馈获得明确确认后，按确认范围进入正文，不再重复询问同义的启动许可。正文后验收通过时，若此前已获得继续推进预览的授权且主论点、作者立场、覆盖范围未改变，可同轮继续预览；正文后验收不是第二次写作授权。若正文暴露核心判断或范围改变，回到对应作者确认节点。
- 后续只改错字、链接、排版或图片尺寸时不重做认知报告；后续完整预览简要交代相较真实开题和上次预览的变化，认知与结构未变时明示即可。机制、章节职责或核心证据发生实质变化时，原位更新受影响的判断与章节关系。

## 2. 起点不能事后被改写

首次正式讨论时保存：原始兴趣/困惑、用户已经明确知道的判断、待验证假设、关键未知与暂定边界。使用用户原话、启动 Prompt 或明确接受过的观点定位基线；已有待办成果属于本次开题已知，原始兴趣触发和本轮独立起点不是同一时点时分别说明。不要把模型后来补充的解释倒填成用户一开始就知道的内容，也不要把启动时已经提出的判断包装成研究后才发现的洞见。

历史检索前独立快照仍按 SOP 的时序执行。从已有会话恢复时，能够核对的起点可回溯重建，但必须注明“回溯整理”；无法确定的认知不能代替用户作主，记为未确认。基线可以随用户纠正，但保留纠正原因。

优先放在该文已有研究/审查记录中。它不是第二份正文，不新增等价 Handoff 文件，不强制每轮重抄。

## 3. 写作前认知增量反馈与作者确认

**触发位置。** 作者明确确认完整大纲后、内部完整初稿开始前执行。该反馈必须先于正文写作，作者确认是正式写作的必要条件。它与大纲确认分开：大纲确认解决“文章结构和范围是否成立”；本阶段解决“研究新增的哪些认识值得进入正文、作者是否接受这些核心判断”。不得把本阶段挪到大纲之前，也不得用正文完成后的认知验收替代。

反馈至少包含以下七项，按本篇实际研究规模组织，不机械追求篇幅：

1. **初始认知与研究后认知的差别**：最初的问题、已知事实和原有判断是什么；经过研究后，哪些判断得到补强、限定、修正或否定。
2. **事实增量**：新增的重要事实、案例和数据分别能证明什么、不能证明什么；明确区分作者观察、厂商自述、独立研究和实际企业实践。
3. **机制增量**：新增的因果关系、参与者分工、成立条件、约束和反例；说明相较原有判断，解释能力具体推进在哪里。
4. **竞争性解释**：最强反方观点是什么，哪些证据支持它，哪些证据可以区分不同解释。
5. **历史文章独立增量**：与高相关已发布文章相比，哪些旧观点只作为必要前提，本文新增了什么判断、机制或决策能力；不能把普通案例复用说成历史增量。
6. **可迁移的判断能力**：读者读完后，能够比以前更准确地判断什么相似问题或反事实。
7. **证据边界**：区分直接事实、研究综合、条件性推论和未知；说明哪些新证据可能改变结论。

各项均区分作者原有判断、研究后明确接受的判断，以及 AI 或来源提出但作者尚未确认的解释；不替作者认领立场。

**作者确认与回退。** 反馈后明确等待作者确认、修正立场、调整范围或要求继续研究。只有作者明确确认这份认知增量及其对应范围、同意进入正文，才能开始内部完整初稿；不能从分类确认、大纲确认或含糊的继续信号推断授权。若作者修正核心判断或范围，先更新受影响的大纲与反馈，再取得确认。作者明确确认后直接进入写作，不再重复询问同义的“是否开始写作”。

## 4. 正文完成后的认知增量反馈

正文完成后的反馈用与文章规模相称的篇幅说明，不能只列章节目录或宣称“形成体系”：

1. **起点与现在的差别**：最初已知/假设是什么，最终保留、补强、限定、修正或否定了什么；没有变化也如实说明。新增事实、解释机制、判断方法和体系连接分开，不把更多案例当作更深解释。
2. **为什么能推进**：每项核心增量指向正文承担它的章节与关键证据/推理。说明证据直接支持什么，哪些是本文综合、条件性推导或尚未验证的外推。
3. **接通了什么**：若连接两个理论、业务层或系统，写明共同变量和作用机制、适用边界，以及连接之后能解释原来解释不了的哪种差异。共同关键词、同属 AI 或放在同一张图上不算连接。
4. **现在能多做什么判断**：给出一个相似问题、反事实或取舍，说明新框架怎样改变问题诊断、选择或需寻找的证据。不必强行改写成 PM 操作手册。
5. **仍然不知道什么**：列最影响主张的证据缺口、竞争解释与推翻条件，避免把理论解释包装成实证结论。

同时区分对本次对话起点的认知推进、相对作者历史文章的独立内容增量和学界原创性，三者不能互相替代。原判断获得有实质证据支持的置信调整也可以构成增量，不要求每篇推翻原观点。作者是否真的学到了新东西仍由作者判断；模型只能展示可检验的解释增量，不能替作者宣布认知已升级。

## 5. 章节关系必须可检查

对每个主要章节说明“接住什么问题/前提 → 用什么论据或机制处理 → 得到什么结论 → 为后文提供什么”。基于实际正文展示简洁论证图；表格或文字路径更清楚时可等价替代并说明关系，不复读目录或预定大纲，不为形式制作复杂插图。

图/表中的每条连接标明是前提依赖、因果机制、并列对照、反证限定还是反馈。阅读顺序不自动等于现实过程的因果顺序；一个案例只能支撑链条的一部分时，不得以箭头替代尚未建立的推断。

检查删除某章后是否丢失必要前提、独立论据或边界；若不丢失，优先合并或删除。检查首尾是否回答同一个统领问题，是否存在循环论证、突然换尺度或把同一结论换词重复。

这是作者审阅用的结构地图，不是正文开头必须再放一张路线图的要求。公开正文是否使用地图，仍按文章类型与图表阅读任务决定；已有清楚目录和过渡时，不重复装饰。

## 6. 最低门槛：点、线、面与迁移

- **点有深度**：核心判断至少新增一个有依据的机制、条件、区别、反例或判断方法；不能只把术语解释得更长。
- **线能接通**：主要推断有必要的中间步骤，结论强度不超过证据；不能由单个案例直接跳到行业终局。
- **面有边界**：覆盖会改变主结论的重要相关方、竞争解释或系统约束；广度服从当前问题，不要求跨多个学科、不机械增加公司和框架。
- **能够迁移**：说明该认识能怎样用于另一个案例或反事实；这是方法适用性检查，不是保证未来预测准确。

以上是解释质量底线，不设置固定框架数、案例数、理论层数或字数。维持原判断但明确了关键成立条件，也可能是真实推进；修正错误、缩小主张和证明确实未知同样有价值。

若只能报告“增加了一些介绍/案例/资料”，或关键推断仍缺前提，不进入以正式成稿名义交付的全局预览。主论证缺证据时定向补证或收窄，有材料却没有形成解释时重组，没有独立增量时缩短、合并或暂缓；不靠拔高结尾和堆同向案例过关。用户明确选择制作基础介绍、资料综述或实践记录时，可以继续，但必须如实定位，不能称为深度判断稿；这种范围选择由用户决定。

## 7. 路由与效率

Blog SOP 维护阶段路由、前后依赖与作者关口，Governance README 负责读取导航；本文件是认知报告内容、章节关系方法、质量门槛与不达标处理的唯一详细规范。发布级预览规范承接正文后验收结果；Checklist 验证实际交付和与正文的一致性，不另维护报告模板。单篇实际判断记入原有审查记录，对作者的回报须在对话中实际交付，不塞入公开正文或 metadata，不新增同义文件。

认知推进在讨论与正文阶段解决，图形制作在语义稳定后开始，发布只处理已批准内容的确定性迁移。主线未被新证据推翻时不重新全网扩题；文件按阶段与实际 SHA 变动读取，不在同一阶段每次全量重读；缺少工具时说明缺口，不把反复试同一路径当成进展。

图形出现同类可读性问题时先换表示方式，而不是只改阴影、颜色或箭头粗细。选图不等于写入，提交不等于部署，部署不等于线上与视觉验收。保留所有实质质量门槛，减少的是重复执行和无效等待。
