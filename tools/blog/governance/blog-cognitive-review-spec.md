# 正文确认前的认知增量与结构验收

版本：1.0｜更新：2026-11-08

本文件补充 Blog SOP 的正文确认与阶段交付，不另建研究方法、评分体系或作者审批流程。适用于从研究待办、系列、新闻链接、聊天兴趣点等入口正式启动的博客。既有 SOP 的研究深度与问题重构、Checklist 的章节贡献与推断层级仍是内容依据；这里规定如何保留认知基线、怎样把结果反馈给作者，以及何时不得进入全局预览。

## 1. 两个检查时点，一个可见反馈

- **大纲确认前预检**：沿用 SOP 的独立起点快照和研究深度检查，说明预期增量是否成立，不额外增加一轮审批。
- **正文确定、全局图文预览之前验收**：完成全文通读、活人感审校和 Checklist 适用项后，必须在当前对话向作者交付“认知增量反馈＋章节关系图/表＋剩余边界”。不能只在内部记录里写“通过”，也不能等到图片制作或正式发布之后才反馈。
- 用户已让模型直接推进且检查通过时，反馈后可继续同轮制作预览，不为流程新增一次“是否继续”确认。涉及主论点、作者立场或覆盖范围改变时，按原 SOP 回到对应确认节点。
- 后续只改错字、链接、排版或图片尺寸时不重做认知报告；机制、章节职责或核心证据发生实质变化时，原位更新受影响的判断。

## 2. 起点不能事后被改写

首次正式讨论时保存：原始兴趣/困惑、用户已经明确知道的判断、待验证假设、关键未知与暂定边界。使用用户原话、启动 Prompt 或明确接受过的观点定位基线；不要把模型后来补充的解释倒填成用户一开始就知道的内容，也不要把启动时已经提出的判断包装成研究后才发现的洞见。

历史检索前独立快照仍按 SOP 的时序执行。从已有会话恢复时，能够核对的起点可回溯重建，但必须注明“回溯整理”；无法确定的认知不能代替用户作主，记为未确认。基线可以随用户纠正，但保留纠正原因。

优先放在该文已有研究/审查记录中。它不是第二份正文，不新增等价 Handoff 文件，不强制每轮重抄。

## 3. 给作者的认知增量反馈

用与文章规模相称的篇幅说明，不能只列章节目录或宣称“形成体系”：

1. **起点与现在的差别**：最初已知/假设是什么，最终保留、补强、限定、修正或否定了什么；没有变化也如实说明。新增事实、解释机制、判断方法和体系连接分开，不把更多案例当作更深解释。
2. **为什么能推进**：每项核心增量指向正文承担它的章节与关键证据/推理。说明证据直接支持什么，哪些是本文综合、条件性推导或尚未验证的外推。
3. **接通了什么**：若连接两个理论、业务层或系统，写明共同变量和作用机制、适用边界，以及连接之后能解释原来解释不了的哪种差异。共同关键词、同属 AI 或放在同一张图上不算连接。
4. **现在能多做什么判断**：给出一个相似问题、反事实或取舍，说明新框架怎样改变问题诊断、选择或需寻找的证据。不必强行改写成 PM 操作手册。
5. **仍然不知道什么**：列最影响主张的证据缺口、竞争解释与推翻条件，避免把理论解释包装成实证结论。

同时区分两种增量：对本次对话起点的认知推进，与相对作者历史文章的独立内容增量。二者不能互相替代。作者是否真的学到了新东西仍由作者判断；模型只能展示可检验的解释增量，不能替作者宣布认知已升级。

## 4. 章节关系必须可检查

对每个主要章节说明“接住什么问题/前提 → 用什么论据或机制处理 → 得到什么结论 → 为后文提供什么”。可以使用简短关系图、论证表或带箭头的文字链；先选最容易读懂的表达，不先制作复杂插图。

图/表中的每条连接标明是前提依赖、因果机制、并列对照、反证限定还是反馈。阅读顺序不自动等于现实过程的因果顺序；一个案例只能支撑链条的一部分时，不得以箭头替代尚未建立的推断。

检查删除某章后是否丢失必要前提、独立论据或边界；若不丢失，优先合并或删除。检查首尾是否回答同一个统领问题，是否存在循环论证、突然换尺度或把同一结论换词重复。

这是作者审阅用的结构地图，不是正文开头必须再放一张路线图的要求。公开正文是否使用地图，仍按文章类型与图表阅读任务决定；已有清楚目录和过渡时，不重复装饰。

## 5. 最低门槛：点、线、面与迁移

- **点有深度**：核心判断至少新增一个有依据的机制、条件、区别、反例或判断方法；不能只把术语解释得更长。
- **线能接通**：主要推断有必要的中间步骤，结论强度不超过证据；不能由单个案例直接跳到行业终局。
- **面有边界**：覆盖会改变主结论的重要相关方、竞争解释或系统约束；广度服从当前问题，不要求跨多个学科、不机械增加公司和框架。
- **能够迁移**：说明该认识能怎样用于另一个案例或反事实；这是方法适用性检查，不是保证未来预测准确。

以上是解释质量底线，不设置固定框架数、案例数、理论层数或字数。维持原判断但明确了关键成立条件，也可能是真实推进；修正错误、缩小主张和证明确实未知同样有价值。

若只能报告“增加了一些介绍/案例/资料”，或关键推断仍缺前提，不进入以正式成稿名义交付的全局预览。先定向补证、重新组织、收窄/缩短，必要时合并旧文或暂缓。用户明确选择制作基础介绍或资料综述时，可以继续，但必须如实定位，不能称为深度判断稿；这种范围选择由用户决定。

## 6. 路由与效率

Governance README 路由本节点；发布级预览规范负责阻止遗漏；Checklist 负责内容审查，不重复复制本文件的报告模板。单篇实际判断记入原有审查记录。

认知推进在讨论与正文阶段解决，图形制作在语义稳定后开始，发布只处理已批准内容的确定性迁移。主线未被新证据推翻时不重新全网扩题；文件按阶段与实际 SHA 变动读取，不在同一阶段每次全量重读；缺少工具时说明缺口，不把反复试同一路径当成进展。

图形出现同类可读性问题时先换表示方式，而不是只改阴影、颜色或箭头粗细。选图不等于写入，提交不等于部署，部署不等于线上与视觉验收。保留所有实质质量门槛，减少的是重复执行和无效等待。
