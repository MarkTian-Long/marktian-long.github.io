## 入选依据

- **项目及入口**：[ai-workflow-kit](https://github.com/MarkTian-Long/ai-workflow-kit/blob/main/README.md)。2026-10-18 核对公开默认分支，README blob `7e98953362014607f9d76bfc455f778fa53cca1d`；[验证范围](https://github.com/MarkTian-Long/ai-workflow-kit/blob/main/VALIDATION.md) blob `4c2f04e417f4c892c3016f9e7eb8da9bfdf7b161`。
- **读者及场景**：需要做分析讨论、会话交接、文档制图、汇报、文件处理的 AI 使用者，不希望为单一任务先搭建整套协作框架。
- **使用价值**：按任务选择独立的 Skill、SOP、模板、图样或小脚本；从 README 的任务导航进入对应使用说明，保留各项依赖和适用限制。
- **作者代表性**：将反复出现的任务方法分解为可独立发布、带使用条件和验证边界的小件，而不仅是展示个人系统的整体设计。
- **可用状态与边界**：公开 README 提供单项入口，验证记录包含本地/合成检查；Skill 的发现、安装与效果须在具体宿主核验，脚本需要按说明安装依赖。不是整包自动安装，也不提供自动调度；不将局部验证宣传为真实用户的长期收益。
- **现有项目区别**：资料库解决内容采集与查阅，本地文件助手解决授权文件接入；Kit 解决单件方法或工具的按需复用；Harness-starter 解决长期协作的规则、任务文件与续接基础。后两者互补，[Harness 的 README](https://github.com/MarkTian-Long/harness-starter/blob/main/README.md)也将 Kit 列为独立小件入口。
- **为什么新增而非替换**：四者任务入口和作者代表性均不同；四项仍在 [精选规范](../github-resources-guidelines.md)允许的 2–4 项范围内。排序为资料库 → 本地文件助手 → Kit → Harness，按具体应用到单项方法再到完整协作框架递进。
