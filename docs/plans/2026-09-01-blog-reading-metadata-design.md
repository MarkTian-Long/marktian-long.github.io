# 博客阅读信息设计

## 目标

在每篇博客文章标题上方的元信息行中显示约计字数和预计阅读时长，让读者在打开文章时就能判断阅读投入。历史文章和新文章使用同一规则。

## 已确认的产品规则

- 显示位置：发布日期之后、标签之前。
- 显示文案：`约 7,800 字 · 20 分钟阅读`。
- 阅读速度：每分钟 400 个阅读单位，阅读时长向上取整且至少为 1 分钟。
- 统计来源：浏览器中最终发布的 HTML 正文，不依赖 Markdown。
- 统计范围：正文标题、段落、列表和表格中的可读文本；排除文章摘要、参考资料、代码块、图片与图注，以及页面导航。
- 字数展示：中文字符加英文/数字词组构成阅读单位，向最接近的百位取整；这是用于阅读预期的近似值，不表示语言学词数。

## 方案比较

1. 在 `posts-meta.json` 手工维护字数与时长：易与正文失同步，不采用。
2. 新文章从 Markdown 生成静态数值：不能覆盖没有 Markdown 的历史文章，且会形成两套口径，不采用。
3. 在 `article-runtime.js` 从已发布 HTML 计算并插入：全部 40 篇文章已加载该共享运行时，并拥有统一的 `.post-meta` 容器；新旧文章一致，不需批量重生成，采用。

## 架构与边界

`article-runtime.js` 新增无副作用的纯函数，用于规范化正文、计数、格式化显示文本。浏览器启动时，在参考资料呈现逻辑完成后读取 `.post-body`，删除不参与统计的节点，再在 `.post-date` 后创建唯一的 `.post-reading-meta` 元素。函数必须能安全地处理缺失的文章容器或空内容；不会请求网络、写入 localStorage，也不会修改文章正文。

视觉样式沿用文章页现有元信息的字级和色彩层级，只使用已有 CSS 变量。元信息必须保持可读、可换行，并让辅助技术读取完整的显示文本。

## 验证

- 先为纯计数和格式化函数编写 Node 测试，覆盖中文、英文词组、四舍五入、最小时长与不计入内容的边界。
- 在每篇已发布文章均加载 runtime 的现有契约基础上，新增对阅读元信息运行时能力的回归断言。
- 用真实本地 HTTP 页面核验一篇新式文章和一篇早期文章，在桌面与移动视口确认位置、换行和内容。
- 运行博客相关单测、搜索基础检查与 public dist 构建/检查。
