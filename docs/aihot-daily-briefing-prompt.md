生成今天的 AIHOT 每日情报。核心目标：在纯 ChatGPT 网页执行环境内尽可能提高 AIHOT 过去 24 小时公开资讯覆盖率，同时严格区分“可证明完整”与“高覆盖但无法证明完整”。不要把缓存页、搜索快照或断裂分页链冒充确定性全集。

【执行规则：严格保留，但不要把抓取日志大段展示给用户】
1. 每次运行前轻量检查 AIHOT 官方 Agent 接入页 https://aihot.virxact.com/agent 与官方 v1 API/Skill 当前合同；GitHub KKKKhazix/khazix-skills 仅作镜像补充。版本冲突时以 AIHOT 官方站和实际接口行为为准。若 API 路由、cursor、时间口径、网页翻页、RSS、日报规则有实质变化，从当次起按最新版执行，并在开头用 1—2 条注明“AIHOT 上游同步”。
2. 第一优先路径仍是 `/api/v1/items?mode=all&window=24h&by=timeline&limit=100`。若可读取 JSON，严格按同一响应的 `page.hasMore` / `page.nextCursor` 连续分页，cursor 原样回传，不解析、不修改、不跨查询或跨天复用。只有同一轮从第一页连续到 `hasMore=false`、无缺页/超时/异常，才判 `A｜已确认全量`，并可报告精确原始条目数 N。
3. REST 动态 cursor URL 若当前网页工具无法请求，或任何页失败，不继续猜 URL；立即进入网页 fallback。REST 因执行环境限制失败时，只记为“REST 分页链未完成”，不要写成 AIHOT API 故障。
4. 网页 fallback：直接打开 `/all`，记录第一页快照签名；后续只点击当前已打开页面真实返回的“下一页”，禁止猜 `/all?page=N`，禁止用搜索引擎历史 page=N 替代连续点击。持续翻到运行时刻前 24h 边界或不可恢复断链。
5. 每页内部继续记录页码、今日条数、最新/最老时间、首尾指纹、成功行数，用于连续性审计；相邻页检查总数漂移、时间倒退后跳新、缓存日期不一致、大量重复和异常断层。时间断层本身不足以证明漏项，必须与其他异常信号共现。
6. 单页超时可对同一真实链接重试最多 2 次。Pass 1 出现超时/快照漂移/疑似断层时才做 Pass 2；Pass 2 从 `/all` 第一页重新开始，仍只沿真实下一页，至少重走到异常页之后 1 页。两遍按 AIHOT 站内链接优先、其次“来源+时间+标题”去重并集。Pass 2 只提高覆盖，不伪造单一快照。
7. 主链异常时，使用网页当前实际提供的分类页（模型、产品、行业、论文、教程、观点等）和来源视图（一手/资讯/X 等）做正交缺口修复；只补异常时间段附近，不机械遍历历史。补到的新独立事件合并进已识别集合并标记“网页修复补录”，但不提升到 A。
8. RSS `/feed/all.xml` 若可读，仅用于最近 7 天公开池对账；RSS 按真实原文时间，与 timeline 不同，不能替代主集合。客户端因 `application/rss+xml` 不支持时只记“RSS 不可读”，不反复尝试。
9. 查询 `/api/v1/hot-topics` 或官方热点榜，只用官方 rank。只有 hot-topics 实际返回 story publicId/links.story 时才调用 `/api/v1/stories/{publicId}`，不猜 ID。Story 只补时间线/digest/latest，不混成新 24h item。
10. Daily 优先 `/api/v1/dailies?limit=1`，API 不可用则用官方 `/daily`。Daily 只做 lead/sections/flashes 编辑层查漏，固定日切与滚动 24h 不混算。`mode=all` 已含 selected/reason 时不再单独查 selected。snapshot/changes 不作为每日公开池补漏入口。交付前重新核实官方最新可读 Daily 的期号、出刊日期及日切窗口，不沿用抓取途中旧快照；当次无法确认时不得宣称已核实最新一期。
11. 事件级去重：同阶段同事件多篇报道合并，把真正新增事实并入一个摘要；AIHOT 已显示“同事件/另有 N 家信源”时优先沿用其聚合关系。不同版本、后续进展、评测、定价、安全调查若信息增量独立则不要误合并。底层原则上保留已抓到的每个独立事件；数据量大时普通事件压成“一行标题 + 一句话”，不要因为篇幅静默删掉。

【覆盖评级：内部严格执行，外部只简洁展示】
A `已确认全量`：仅 REST cursor 同轮完整翻至 hasMore=false。
B `高覆盖，未确认全量`：REST 不完整，但网页主链至少连续触达 24h 边界；若出现异常已执行 Pass 2；hot-topics 与 daily 至少一项成功。
C `覆盖不完整`：网页主链明显缺页且 Pass 2 未恢复到 24h 边界，或主集合主要路径失败。

【重要的展示调整】
- 不再输出“覆盖审计”大表格，不逐页展示 Pass 1 / Pass 2 / Page 1 / Page 2、重试次数、原始行位点、分类修复明细等抓取日志。
- 这些审计信息继续在执行过程中严格记录和用于 A/B/C 判级，但用户只看结果，不看过程日志。
- 日报开头只保留 1 个非常简洁的覆盖状态块：
  `覆盖级别：B｜高覆盖，未确认全量`
  `覆盖说明：REST 分页链未完成；网页主链已触达 24h 边界；仍可能漏实时长尾。`
  最多 1—2 句。若为 C，只额外指出关键缺口区间或主要失败点；若为 A，可报告精确 N。不要再重复后续审计表。
- RSS / Hot Topics / Story / Daily 的成功与否，只在会影响内容解释时用一句话并入“覆盖说明”或 C 部分，不单独列日志表。

【输出结构】
标题：`AIHOT 每日情报｜YYYY-MM-DD`
开头：简洁覆盖级别 + 1—2 句覆盖说明；有实质上游变化时再加 1—2 条“AIHOT 上游同步”。
A. `今天先看这 3—5 件事`
- 只是整个已识别事件集合的重点阅读入口，不是另一套数据源，也不要创造 B 中不存在的新事实。
- 每条写：发生了什么 + 为什么重要 + 精选/热点标签 + AIHOT 站内链接；关键数字/政策/原话必要时回原始来源核验。
- A 选题前从 B 的已识别事件集合做跨主题重要性复核，特别检查正式公布或生效的重大政策／出口管制、监管执法、重大安全事故、产业基础设施变化和重要商业合作。综合比较事实增量、影响范围、约束强度、证据可靠性和结构性影响，不只按 AIHOT 热度或报道数量排序；重大事件必须纳入候选比较，但不强制占 A 名额。
B. `过去 24 小时动态（事件级去重）`
- 直接进入内容分类，不再放“覆盖审计”表。
- 展示本轮已识别事件集合；A 级可称完整集合，B 明确仍可能漏实时长尾，C 只展示确认内容。
- 按主题分组，如 Agent/Harness/Coding、模型/多模态/Eval、安全/治理、行业/基础设施/产品等；不要为了固定分类强塞内容。
- A 中已经详细展开的事件，在 B 中可以压缩为一行，避免重复大段说明，但仍保留其在事件全集中的位置。
- 已取得 AIHOT 具体事件页时，B 优先采用真实 `/items/` 直达链接，不用 `/all?page=N` 代替已知直链；无法找到时保留已验证的站内位置，不猜测 item ID。重大政策应核对主管机关原文，区分提案、正式公布、计划生效、实际生效与过渡安排。
C. `额外补充`（0—3 条）
- 仅放持续热点、Story 必要背景、AIHOT Daily 编辑层查漏。
- 这些内容不是 24h 主集合的新 item 时，明确标注来源类型，不混算。
D. `今天真正改变了什么`
- 最多 3 条趋势判断，只能从本轮确认事实抽象，不新增未经支持的新事实。

【A/B/C/D 的关系】
- A = 从 B 的已识别事件集合里挑出的 3—5 个最高价值阅读入口；它不是独立来源。
- B = 主体，来自过去 24h 主集合 + 必要网页修复后的事件级去重集合。
- C = 主集合之外的编辑层/持续事件补充，例如 Hot Topics、Story、Daily；默认不计作新的 24h item。
- D = 对 A/B/C 已确认事实的趋势抽象，不是新数据源。
- A 初选后反查 B 是否存在影响范围更广、约束力更强或事实增量更独立、却只被压缩为普通动态的事件；若存在，重新比较 A 的 3—5 个名额，必要时替换较低优先级事件。该反查只影响精选编辑，不改变 B 的底层事件集合或 A/B/C 覆盖评级。

【Markdown 与版式——2026-10-15 更新：严格修复加粗标记裸露问题】
1. 分类标题统一使用 `###` 小标题，不写 `**分类：**正文`。
2. 分类下一个独立事件一个项目符号；同类超过 3 个事件必须拆项目符号，避免文字墙。
3. **事件列表必须统一采用 `- **事件标题**：一句话说明` 格式**，标题加粗区域内部只放简洁标题，不含末尾句号或冒号；标题与说明由加粗结束标记外面的中文冒号分隔。禁止 `- **事件标题。**正文`、`- **事件标题。 **正文`、`- **事件标题： **正文` 等格式。确实无法保证解析时，直接使用不加粗的 `- 事件标题：说明`，禁止输出裸露的星号。
4. 加粗标记必须成对且紧贴被强调的实际文字：不得有 `** 标题**` 或 `**标题 **`；不要把引用、站内链接、citation 塞在同一对加粗标记里；在文本中出现字面 `**` 时使用行内代码保护。
5. **生成完毕后强制进行一次 Markdown 格式验收**：逐条检查项目符号内是否存在未闭合 `**`、星号直接裸露、加粗结束符后立即跟正文而没有明确分隔符、反引号不匹配、标题井号裸露等异常。重点检查长列表、带中英文混排的事件标题和引用紧邻处。格式不稳就移除该条加粗，不丢弃事件事实。
6. 中文为主；重要英文术语首次出现附简洁中文解释；时间统一转北京时间；优先 AIHOT 站内链接。
